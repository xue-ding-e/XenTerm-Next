## 2. 本轮新发现(旧报告未收录)

### N-高1 russh-sftp 2.1.1 无上限包长分配 —— 恶意 SFTP 服务器单包 ~4 GiB 提交

- **等级**:高 ｜ **CWE**:CWE-789(未受控内存分配)
- **位置**:`~/.cargo/registry/src/.../russh-sftp-2.1.1/src/utils.rs:12-21`(`read_packet`),xenterm 无任何本地缓解
- **证据(已逐行复核本机 registry 源码)**:

```rust
pub async fn read_packet<S: AsyncRead + Unpin>(stream: &mut S) -> Result<Bytes, Error> {
    let length = stream.read_u32().await?;
    let mut buf = vec![0; length as usize];
    stream.read_exact(&mut buf).await?;
    Ok(Bytes::from(buf))
}
```

- **攻击**:恶意(或被攻陷的)SFTP 服务器对任意应答返回长度 `0xFFFFFFFF` → 立即 ~4 GiB 零初始化分配(Windows 计入 commit charge,数包即耗尽页面文件);`read_exact` 挂起期间分配一直持有。xenterm 每次下载/上传各开一个全新 `RawSftpSession`(src/sftp/impls/sftp.rs:1962、2267),递归下载每文件一个(:2140),放大触发频度。OpenSSH sftp-server 缓冲约 256 KiB,该上限在协议上完全够用。
- **修复**:上游修复,或本地 patch/fork 在会话层包一层带 1 MiB 上限的读取器(所有 `read_packet` 调用点均经由 `RawSftpSession`,包装点集中)。

### N-中1 多行粘贴预览按字节截断,非字符边界切片 panic(默认配置可达)

- **等级**:中 ｜ **CWE**:CWE-1287 / CWE-20
- **位置**:`src/ui/impls/view.rs:877-890`(`review_paste`)
- **证据(已逐行复核)**:

```rust
const PREVIEW_LIMIT: usize = 4000;
let shown = if paste.text.len() > PREVIEW_LIMIT {
    let mut cut = paste.text[..PREVIEW_LIMIT].to_string();   // 字节切片,非字符边界即 panic
```

- **触发链(已核实每一环)**:`paste_confirm` 默认开启(config_file.rs:155-158)→ 多行粘贴进预览(input.rs:126-129)→ 远程服务器输出 >4000 字节含换行的 CJK 文本 → 用户拖选(松开自动入剪贴板,view.rs:484-497)→ 粘贴 → 纯 CJK 3 字节/字符,4000 落在码点中间概率极高 → **UI 线程 panic,整个窗口崩溃**。即使关闭确认,>100 KiB 粘贴仍强制进预览(`PASTE_REVIEW_LIMIT`)。
- **修复**:`floor_char_boundary`(Rust 尚未稳定)或用 `char_indices` 找 ≤4000 的最大边界再切。

### N-中2 OscDiscard 不认 CAN/SUB 为 OSC 终止符 —— 恶意服务器可永久冻结终端显示

- **等级**:中 ｜ **CWE**:CWE-1284(错误输入验证 → DoS)
- **位置**:`src/terminal/impls/term_buffer.rs:799-813`(`e6d063e` 新增)
- **证据(已逐行复核,并与 vte 0.11.1 `table.rs` 的 Anywhere 规则对照)**:

```rust
CsiState::OscDiscard => {
    if byte == 0x07 { self.csi_state = CsiState::Normal; }
    else if byte == 0x1b { self.csi_state = CsiState::OscDiscardEsc; }
}   // 0x18(CAN)/0x1a(SUB) 不终止 —— vte 在任意状态都以此二者回到 Ground
```

- **攻击**:服务器发 `\x1b]0;` + >4 KiB 填充(进入 OscDiscard)+ `\x18` + 之后不含 BEL/ESC-\ 的正常输出。基于 vte 的终端(xterm 等)在 CAN 处结束 OSC 正常显示;xenterm 把 **CAN 之后的全部输出静默丢弃**,终端看起来彻底冻结(会话本身存活)。后续真实 CSI 序列里的 ESC 也会被吞(ESC→OscDiscardEsc→非`\`→回 OscDiscard)。缓冲态 `Csi`/`Osc`/`OscEsc` 同样不认 CAN/SUB,但因字节原样转发给 vt100,仅本地状态机短暂失配,危害小。
- **修复**:四个 OSC 相关状态(`Osc`、`OscEsc`、`OscDiscard`、`OscDiscardEsc`)中,0x18/0x1a 一律按终止处理(缓冲态 flush 回 Normal,丢弃态直接回 Normal),对齐 vte 的 Anywhere 规则。

### N-中3 `kill_remote_process` 的 `String::truncate` 非字符边界 panic

- **等级**:中 ｜ **CWE**:CWE-1287
- **位置**:`src/ssh/impls/ssh.rs:749-751`
- **证据(已逐行复核)**:

```rust
if response.len() < 1024 {
    response.push_str(&text);
    response.truncate(response.len().min(1024));   // 1024 落在多字节字符中间即 panic
}
```

- **触发**:特权(sudo)杀进程通道的远端输出。若一次 push 越过 1024 字节且第 1024 字节落在多字节字符中间(如中文 sudo 提示),`String::truncate` 断言失败。该代码在 `tokio::spawn` 任务中,panic 使 oneshot `reply` 被 drop,**等待方永远收不到结果**(panic=unwind,进程不死但功能失效)。
- **修复**:按字符边界截断(逐 char 累积或找边界索引);全仓同类模式仅此一处。

### N-中6 PPK Argon2 参数上限过宽 + KDF 在 tokio worker 上同步执行(runtime 冻结)

- **等级**:中 ｜ **CWE**:CWE-400
- **位置**:`src/ssh/impls/ppk.rs:22-24`(MAX 1 GiB / 1000 passes / 64 lanes)、:198 与 :258(`derive_keys` 解密、验 MAC 各算一次);调用链为 async `authenticate_session` → `load_session_private_key`,无 `spawn_blocking`

- **修复**:PuTTY 实际文件 t≤30,passes 上限收到 ≤100 并对 memory×passes 总量设限;KDF 移入 `spawn_blocking`;顺带修掉重复派生(旧 M-16)。

## 4. 两个性能提交(f188cf5 / e6d063e)专项安全结论

逐项与 vte 0.11.1 状态机对照后的结论:

| 机制 | 结论 |
| --- | --- |
| plain-run 快速路径(不复制、不逐字节状态机) | ✅ 与 vt100 引导符语义一致:`is_plain_run` 只拦 0x1b/0x0e/0x0f(及 DEC graphics 激活时 0x60-0x7e);vte 0.11 不把 8-bit C1(0x9b 等)当序列引导符,两条路径喂给 vt100 的字节流等价,**不存在借 8-bit CSI 绕过 CSI 3 J 扫描** |
| CSI 3 J 尾窗检测(raw 尾 3 字节 + 新块) | ✅ 跨块正确;ESC 在任何状态(含 OSC 内)都开启新序列,窗口内假阳性与 vte 行为一致;`drain(..end)` 无越界 |
| OSC >4 KiB 丢弃态 | ⚠️ 0x07 与 `ESC \` 正确退出,但**缺 CAN/SUB**(N-中2) |
| CSI cap 64→1024 | ✅ 超限中段放行的残余字节最终仍全部到达 vt100,不会持续损坏;仅 DEC graphics 激活时超长残余参数的 0x60-0x7e 字节字符集翻译有显示级差异;无 off-by-one(判 push 之后的 `>`,最大缓冲 1025) |
| alt-screen 原地 resize / reflow | ✅ 逻辑正确;vt100 `set_size` 同时调整主/备 grid,rows≥1 下无下溢;**rows=0 当前全仓不可达**(所有构造点已核实:view.rs 24×80、grid_size 钳 ≥1、测试 3×30/4×20 等),但 `reflow`/`TermBuffer::new` 自身不钳制,建议入口 `.max(1)` 防未来调用点 |
| replay Vec(替代 VecDeque) | ✅ 有界:唯一 extend 点后必调 `cap_raw`(≤2 MiB,削到行边界,无换行则整体清空) |
| PARSER_SCROLLBACK 5000→0 | ✅ 净省 ~40 MB/标签页,无功能回归(自绘 history 不依赖它) |
| O(1) 绝对行号映射 | ✅ hist ≤100k + rows ≤65535 下 usize 无溢出;view_offset 所有写点有 clamp |
| 搜索不预折叠 | ⚠️ ASCII-only 折叠是非 ASCII 行为回归(N-信息3),有意取舍 |
